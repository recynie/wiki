# 数据工程

## 概述

数据工程是构建和维护大规模数据处理系统的学科，专注于数据的采集、存储、转换和分析。

## 核心概念

### ETL（Extract-Transform-Load）

ETL 是将数据从源系统提取、转换后加载到目标系统的过程。

```
┌─────────┐    ┌──────────┐    ┌─────────────┐    ┌──────────┐
│  Source │───▶│ Extract  │───▶│ Transform   │───▶│   Load   │
│  System │    │          │    │ (清洗/转换)   │    │ (目标存储) │
└─────────┘    └──────────┘    └─────────────┘    └──────────┘
```

**Extract（提取）**：从数据库、API、日志文件等源系统获取数据

**Transform（转换）**：数据清洗、格式标准化、字段映射、聚合计算

**Load（加载）**：写入数据仓库、数据湖或目标存储系统

### 数据管道（Data Pipeline）

数据管道是自动化数据流动的架构模式，实现数据的持续采集、处理和传递。

**关键特性**：

- **可靠性**：失败重试、checkpoint、数据一致性保证
- **实时性**：支持流式处理（Kafka、Flink）与批量处理（Spark）
- **可观测性**：数据血缘追踪、质量监控、延迟告警

**常见架构**：

| 模式 | 工具 | 适用场景 |
|------|------|----------|
| Lambda 架构 | Kafka + Spark + HBase | 既有批处理又有实时需求 |
| Kappa 架构 | Kafka + Flink | 纯流式处理，统一代码库 |
| 微服务数据管道 | Airflow + Python | 复杂业务流程编排 |

### 数据仓库（Data Warehouse）

数据仓库是面向主题的、集成的、相对稳定的数据集合，支持管理决策分析。

**核心特性**：

- **面向主题**：按业务主题组织（用户、商品、订单）
- **集成性**：整合多个异构数据源
- **相对稳定性**：历史数据不可更新，主要用于查询
- **时变性**：包含时间维度的历史数据

**数仓分层架构**：

```
┌─────────────────────────────────────────────────────────┐
│                    数据应用层 (Application)              │
│         BI报表 / 数据API / 数据产品 / 机器学习             │
├─────────────────────────────────────────────────────────┤
│                    数据服务层 (Data Service)             │
│         汇总指标 / 宽表层 / 特征工程 / OLAP Cube           │
├─────────────────────────────────────────────────────────┤
│                    数据明细层 (Data Detail)              │
│         ODS / DWD (明细事实表) / DIM (维度表)             │
├─────────────────────────────────────────────────────────┤
│                    原始数据层 (Raw Data)                 │
│         日志 / 埋点 / 业务库原始备份 / 第三方数据          │
└─────────────────────────────────────────────────────────┘
```

## 数据建模方法论

### 维度建模（Kimball）

星型模型以事实表为中心，维度表围绕展开：

- **事实表**：存储业务度量（销售额、订单量）
- **维度表**：描述业务实体的属性（时间、商品、地区）

###  Data Vault 建模

适合企业级数据仓库，支持审计追踪：

- **Hub**：核心业务实体（Customer, Product）
- **Link**：实体间关系
- **Satellite**：实体属性变化历史

## 数据质量保障

数据质量六大维度：

1. **完整性**：无缺失值
2. **准确性**：数据真实反映业务
3. **一致性**：跨系统数据口径统一
4. **及时性**：数据及时更新
5. **唯一性**：无重复记录
6. **有效性**：符合业务规则约束

**质量监控实践**：

- 自动化数据质量检测任务
- 异常数据自动告警
- 数据血缘追踪

## 最佳实践

- **增量优于全量**：优先实现增量同步，减少资源消耗
- **Schema 演变**：支持表结构平滑变更
- **幂等性**：保证数据管道可重复执行
- **监控告警**：覆盖数据延迟、数据量波动、质量异常
